摘要

本实验先复现 DARTree Qwen3-4B Table 1 的核心结果，再围绕 proposal construction、target verification budget、分层验证和两卡流水做训练无关系统探针。正式复现覆盖 7 个数据集、温度 0/1、fixed/pruned DARTree，共 28 份完整结果，接受长度与论文宏平均高度一致。

DARTree pruned 的本地宏平均加速为 7.55×（T=0）和 6.36×（T=1），论文为 6.99× / 5.93×。A100 上 target verification 在 17–257 个真实 tree queries 间约为 37 ms，B256 相对 B64 的 TPOT 改善 10.48%；但更宽构树、早层剪枝和 naive 两卡 chunk pipeline 均没有形成额外收益。

四组 DARTree 的逐数据集 τ 平均相对误差约 0.8%–1.0%，且所有 28 份正式 JSON 样本数正确、非法 token 为 0。结果复现了论文中的整体排序与主要 acceptance 收益。

DARTree 的贡献不只是“把树做大”：它为每条分支维护独立 Domino GRU 状态，使候选分布依赖具体路径前缀，再把分支条件化与 GPU 的横向验证容量结合。

3. Bandwidth-aware 验证预算

真实 tree query roofline 使用 32 个 prefix、每档 160 次测量。A100 上 17–257 queries 的 target forward 均约 37 ms；257-query 相对原始 65-query 只差 0.01%，513-query 则增加 11.69%。这说明权重读取主导下存在一段“多验证节点近乎免费”的平台区。

4. Construction 与 verification 解耦

实验在 GSM8K、HumanEval、Alpaca 上完成 21 个正式配置，将 supertree construction width W 与最终 target verification budget B 分开扫描。

  • 固定 W48 时，B256 相对 B64 的宏平均 TPOT 改善 8.92%，acceptance 提高 12.13%。
  • 固定 B64 时，W12 扩到 W48 使三个数据集分别变慢 0.21%、1.28%、4.37%。
  • 固定 B256 时，GSM8K 最优 W16，Alpaca 最优 W48，HumanEval 在 W24–48 间接近。
  • W48 相对 W16 在 GSM8K 变慢 3.36%，在 Alpaca 加速 6.96%，说明构树宽度应由输入不确定性选择。

因此更准确的控制策略是：hardware-selected verification budget + uncertainty-selected construction width。未用满的 target budget 是独立收益来源，但 proposal 搜索本身并不免费。

5. 两个 No-Go 探针

5.1 Progressive verification

在 5,103 个真实 decoding rounds 上，目标模型第 12/36 层将 64 节点剪到 32 节点，只保留 77.64% 接受长度；加入 DARTree prior 的最佳已测 hybrid 为 89.05%，均低于预设 95% 门槛。早层表示不足以可靠排序最终接受路径，不建议实现复杂的分层 target runtime。

5.2 两卡 tree chunk pipeline

将 target tree queries 拆成 2 chunks 时，理想双卡 verification 上界为 4.485 ms/token，仍比 monolithic 的 2.946 ms/token 慢 52.2%；预测端到端 TPOT 为 5.541 ms，比原始 3.972 ms 慢 39.5%。每个小 chunk 都近似重复支付一次权重流成本，4/8 chunks 更差。

chunked shadow 中同轮接受路径一致，但 BF16 query-shape drift 会进入 DFlash target feature context 并跨轮放大，因此完整生成不保证 bitwise equivalent。该探针不能替代真实双卡 P2P 测量，但已足以否定当前单请求 naive 切块方案。

7. 结论与限制

  1. DARTree Qwen3-4B 的核心 acceptance 结果得到高精度复现，速度排序与论文一致。
  2. A100 上 B256 位于验证平台区，能把未饱和 target budget 转为真实端到端收益。
  3. 构树宽度应与 verification budget 解耦，并依据输入不确定性调整。
  4. 早层 target pruning 和 naive 单请求两卡 chunk pipeline 当前均为 No-Go。
  5. 未完成 Qwen3-4B 同配置 DFlash/DDTree、Qwen3-8B 与论文 Table 2–4 全矩阵；历史运行也早于当前 clean-gate 规范。
