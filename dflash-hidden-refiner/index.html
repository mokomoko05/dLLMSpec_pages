DFlash 前一位置 Hidden Refiner 实验

冻结 DFlash backbone，以同一并行块中前一槽位的 hidden state 修正后一槽位 logits

实验时间
2026-08-29—31
硬件
4 × NVIDIA A100 80GB PCIe
模型
Qwen3-8B / DFlash block-16
状态
训练与真实成对评测完成；数据分布不对齐

摘要

本实验给已经训练好的 DFlash（Block Diffusion for Flash Speculative Decoding，块扩散快速推测解码）增加一个低秩 residual head。DFlash 一次并行产生 15 个 proposal token；新 head 不做逐 token 自回归循环，而是读取第 i−1 个槽位的最终 hidden state，生成一个词表维度的 logit 增量，加到第 i 个槽位的原始 logits 上。DFlash backbone、target embedding 和语言模型输出层全部冻结，训练参数只有约 1,997 万个。

5K、追加 5K 和 30K 三个阶段的离线 validation 都显示正向变化；30K 阶段 full top-1 accuracy 从 0.3194 提高到 0.3327，离线 expected accepted length（EAL，期望接受长度代理值）从 1.7398 提高到 1.8788。但是在 GSM8K、MATH-500、HumanEval 和 MBPP 各 128 条 non-thinking greedy 生成中，平均每轮接受的 draft token 宏平均从 5.5010 降到 5.3227，下降 3.24%，四个数据集和 15 个 proposal 位置均未出现总体改善。

本轮结果存在明确的数据分布问题：5K 与 30K 训练 JSONL 的每一条 assistant response 都包含 <think>，而正式推理使用 Qwen3 non-thinking chat template。官方 DeepSpec 的 Qwen3 checkpoint 则使用对应 target model 在 non-thinking 模式下重新生成的 Open-PerfectBlend response。因此当前负向在线结果不能直接证明 refiner 结构无效；它首先说明“在 thinking 轨迹上训练、在 non-thinking 轨迹上部署”的 head 会破坏原本较强的 non-thinking DFlash。与此同时，逐位置 loss 和离线 EAL 也没有完整模拟连续前缀接受过程，后续即使换成 non-thinking 数据仍须以真实 acceptance 为最终判断。

1. 问题与实验边界

DFlash 把一个已确认 token 作为 anchor（锚点），在它后面放置多个 mask token，并通过一次非自回归 draft forward 并行预测一个 block。Qwen3-8B 的公开 DFlash block-16 checkpoint 每个 block 有 16 个槽位：slot 0 是 anchor，slot 1—15 是 proposal（候选）位置。目标模型随后一次验证这些候选，只提交从 slot 1 开始连续正确的前缀。

Backbone（主体网络）指已经训练好的 DFlash transformer；hidden state（隐状态）是它在某个槽位输出的 D 维连续向量；logits 是语言模型输出层对词表中每个 token 给出的、softmax 之前的未归一化分数。原始 DFlash 使用每个槽位自己的最终 hidden state hi 产生 logits。实验问题是：同一 block 中 hi−1 是否包含原输出层没有充分利用、但能修正 slot i 的信息？第一版特意保持最小化，只测试这一条信息路径。

表 1. 本版包含和不包含的机制
包含不包含

低秩非线性 logit residual完整前一位置 logits 或 soft-token embedding

这里的“前一位置”是 DFlash 并行 block 内的相邻槽位，不是严格自回归模型中“只看见真实前缀到 i−1”的状态。同一 block 内的 draft 槽位按照 DFlash 的非自回归 attention mask 共同计算，因此 hi−1 是并行草稿表示，而不是新增的真实 token 信息。

2. 新增结构

2.1 张量定义

记 N 为当前 packed batch 中抽取的 anchor block 数，B=16 为 block size，D=4096 为 DFlash hidden size，R=128 为 refinement bottleneck rank，V=151936 为 Qwen3-8B 词表大小。DFlash backbone 对所有 block 输出：

\(H\in\mathbb{R}^{1\times N\times B\times D}\) \(L^{\mathrm{base}}=\operatorname{LMHead}(H)\in\mathbb{R}^{1\times N\times B\times V}\)

新增 head 有两个无 bias 的线性层。下投影把 4096 维 hidden 压缩到 128 维，SiLU（Sigmoid Linear Unit）提供非线性，上投影再恢复到整个词表：

\(W_{\mathrm{down}}\in\mathbb{R}^{R\times D},\quad W_{\mathrm{up}}\in\mathbb{R}^{V\times R}\) \(\Delta L_{n,i}=W_{\mathrm{up}}\operatorname{SiLU}(W_{\mathrm{down}}h_{n,i-1}),\quad i=1,\ldots,15\) \(L^{\mathrm{refined}}_{n,i}=L^{\mathrm{base}}_{n,i}+\Delta L_{n,i}\) \(\Delta L_{n,0}=0\)

实现先把展平的 [1, NB, D] 恢复为 [1, N, B, D]，只取每个 block 的 hidden slot 0—14，得到 [1, N, 15, D]。head 输出 [1, N, 15, V] 后，在 slot 维前面拼接一个全零张量，再与 [1, N, 16, V] 的 base logits 相加。这样 slot 1 使用 slot 0，slot 15 使用 slot 14；一个 block 的 slot 15 不会越界修正下一个 block 的 slot 0。

2.2 为什么使用 residual 和零初始化

上投影 Wup 初始化为严格全零，因此训练开始时所有 ΔL=0，refined logits 与 base DFlash 逐元素一致。第一步反向传播先更新 Wup；当它离开零点后，梯度才进一步进入随机初始化的 Wdown。这种 residual 初始化提供一个清楚的不变量：step 0 若改变 base 输出，说明 shift、checkpoint 加载或 dtype 路径存在实现错误。

rank-128 head 的参数量为 R(D+V)=19,972,096。BF16 权重约 38.1 MiB；参数本身不大，但每个有效位置都产生 V 维 residual。在 1,536 anchors、每 block 15 个修正位置时，宽词表中间激活是显存和训练吞吐的主要新增成本。

3. 训练数据流

训练采用 Speculators 的 online hidden-state 流程。“Online”只表示冻结 target 的 hidden states 按 batch 即时生成；target model 不参与反向传播，也不更新权重。

  1. 读取对话。JSONL 中每条记录包含 user/assistant turns。tokenizer 按训练数据原有完整对话编码，构造 input_ids、只监督 assistant 区间的 loss_mask、文档边界和 position IDs。
  2. Target hidden-state server。GPU 0 上的冻结 Qwen3-8B vLLM server 接收同一 token 序列，返回 target 第 2、10、18、26、34 层的 hidden states，以及用于构造 teacher 分布的 final hidden state。
  3. 多层压缩。五层 target hidden 在最后一维拼接，经 DFlash 已训练的线性层和 RMSNorm 压回 D=4096，形成每个真实 token 的 target context feature。
  4. 抽取 anchors。trainer 从有效 assistant token 位置抽取最多 1,536 个 anchor。每个 anchor 扩展为 16 槽 block：slot 0 放真实 anchor token，slot 1—15 放 DFlash mask token。
  5. 冻结 DFlash forward。mask embeddings 经过五层 DFlash draft transformer，并按照 anchored-block attention mask 读取真实 target context，输出形状为 [1, NB, D] 的 H 和 base logits。
  6. 构造 teacher logits。冻结 target 的 final hidden state 经 target RMSNorm 和 LM head 投影到词表。索引相对 anchor 做一位对齐，使 slot i 的 teacher distribution 对应训练序列中该 proposal 位置的真实 target 分布。
  7. 应用 refiner。将 H 恢复 block 维，执行严格的同 block 一槽右移，产生 refined logits。slot 0 在 loss mask 中被排除。
  8. 计算 loss 与反向传播。只对 refined logits 计算 CE、TV 和位置衰减；GPU 1—3 以 distributed data parallel（DDP，分布式数据并行）同步两个 head 权重的梯度。
  9. 消费缓存。本轮 online 配置为 on-missing=generate、on-generate=delete，target hidden-state 临时文件被 trainer 读取后删除。

4. 监督目标与 Loss 设计

4.1 Teacher 与 student 分布

对每个有效 proposal 位置 j，记 target model 的 teacher logits 为 Tj，refiner 输出为 Lj。二者经过 softmax 得到 target distribution pj 和 draft distribution qj：

\(p_j(v)=\operatorname{softmax}(T_j)_v,\quad q_j(v)=\operatorname{softmax}(L_j)_v\)

4.2 Cross-entropy 项

CE（cross-entropy，交叉熵）先取 target distribution 中概率最大的 token，记为 yj，再最大化 student 对该 token 的概率：

\(\mathcal{L}_{\mathrm{CE},j}=-\log q_j(y_j)\)

这一项关心 greedy top-1 是否靠近 target，梯度集中推动 target 最大概率 token。

4.3 Total variation 项

TV（total variation distance，总变差距离）比较完整词表分布。对推测解码的标准 rejection sampling，draft 与 target 的分布重叠记为 αj，单位置 TV 等于 1−αj：

\(\mathcal{L}_{\mathrm{TV},j}=1-\sum_{v=1}^{V}\min(p_j(v),q_j(v))\)

因此 TV 在给定同一前缀、同一位置时直接推动 target/draft distribution overlap；它不只匹配 argmax，也调整非最大概率 token 的概率质量。

4.4 复合 loss 与位置衰减

本轮沿用此前 DFlash/DSpark 配置：

\(\ell_j=0.1\,\mathcal{L}_{\mathrm{CE},j}+0.9\,\mathcal{L}_{\mathrm{TV},j}\) \(w_0=0,\quad w_j=\exp(-(j-1)/4),\quad j=1,\ldots,15\) \(\mathcal{L}=\frac{\sum_{n,j}m_{n,j}w_j\ell_{n,j}}{\sum_{n,j}m_{n,j}+10^{-5}}\)

mn,j 是 assistant/padding/anchor 对齐后的 loss mask。slot 0 是输入 anchor，所以权重为 0；越靠后的 proposal 位置权重按 γ=4 指数下降。代码中的分母是有效 mask 数，而不是位置权重之和，因此衰减同时改变了不同位置的相对权重和总 loss 尺度。

4.5 为什么离线 EAL 不是实际接受长度

validation 先独立统计每个 slot 的 marginal top-1 accuracy aj，然后计算：

\(\mathrm{EAL}_{\mathrm{proxy}}=\sum_{k=1}^{15}\prod_{j=1}^{k}a_j\)

它用“各位置准确率的乘积”近似连续前缀正确概率，但没有在同一个真实 block 上逐条统计首次错误位置，也没有让 refined proposal 改变下一轮生成前缀。不同位置的错误高度相关时，边缘准确率乘积可以偏离真实 prefix acceptance。更重要的是，训练和 validation 都在 teacher-forced 数据前缀上计算；真实 speculative decoding 的后续 block 由当前轮实际接受结果决定。因此本页把它明确记为 offline EAL proxy，而不是线上 acceptance length。

5.1 初始化与 smoke

  1. 从公开 Qwen3-8B DFlash block-16 checkpoint 转换并加载完整 backbone。
  2. 新建 rank-128 head，令 up_proj.weight 为严格全零。
  3. 冻结除 refinement_head.* 外的全部参数。
  4. 运行小规模 forward/backward，检查 step 0 refined/base 完全一致、首次 optimizer step 后上投影离开零点、无 OOM/NaN。

5.2 性能调参与 5K pilot

无 DataLoader 预取时，每个 rank 主进程同步等待 target hidden states，单步约有 2.2 秒 fetch。加入一个 worker 后，下一批 hidden-state 请求与当前 batch 的 draft forward/backward 重叠；1,536-anchor benchmark 的显式 fetch 约降到 16 ms。1,664 anchors 只比 1,536 快约 4%，但显存快照达到约 73.6/81.9 GiB，因此正式配置选择 1,536 保留长期运行余量。

正式 5K pilot 使用 learning rate 3 × 10−4，训练 1 epoch / 1,204 steps。训练主体 36 分 15 秒，validation 65 batches / 2 分 9 秒，完整 launcher 39 分 47 秒；没有 OOM、NaN、NCCL 或 HTTP failure。

5.3 追加 5K gate

从 5K pilot checkpoint 继续训练同一 5K split 一轮，learning rate 改为 1 × 10−4。Gate 只比较“refined 减 base”的增量：full accuracy 增量必须高于上一轮的 +0.010984，EAL 增量必须高于 +0.106206。追加一轮得到 +0.011229 和 +0.110388，因此 gate 通过。

5.4 30K 扩展

Gate 通过后，从追加 5K checkpoint 初始化，在与 pilot 不重叠的 30,000 条数据上训练 1 epoch，seed 43，learning rate 1 × 10−4。训练 7,213 steps / 3 小时 46 分 42 秒，validation 374 batches / 10 分 58 秒；完整 staged 流程在 2026-08-30 17:00 结束。

7. 推理数据流

训练 checkpoint 只保存两个 refiner 权重；原生 DFlash runtime 仍从公开 DFlash checkpoint 加载 backbone，并从 Qwen3-8B target 加载 embedding 与 LM head。加载器检查 hidden size、词表大小、block size 和 target layer index 映射，避免把不兼容 head 静默接入。

  1. 对当前已确认 target prefix 建立 target 与 draft key-value cache（KV cache，注意力键值缓存）。
  2. DFlash 在 anchor 后放置 15 个 mask，一次 forward 输出完整 16-slot hidden：h0, …, h15。
  3. 原始 proposal logits 从 h1, …, h15 经冻结 target LM head 得到。
  4. refiner 必须保留完整 block hidden，从 h0, …, h14 计算 residual，并逐项加到对应的 15 个 base proposal logits。若先裁掉 anchor 再 shift，会让所有位置错一格。
  5. 对 refined logits 做 greedy argmax，得到 15 个 proposal token。
  6. target model 在正确 KV cache 上一次验证 proposal，接受从开头连续相同的 draft tokens，并给出一个 target bonus token。
  7. 更新已确认前缀与 cache，进入下一轮；任何被拒后缀都不会直接提交。

成对评测对每个 prompt 运行两次完整生成：一次关闭 head 得到 base DFlash，一次打开同一 head 得到 refined DFlash。两次各自重建 cache，后续上下文由各自真实接受结果决定。temperature 为 0，因此正确的推测解码无论 proposal 如何变化，都必须保持 target greedy 输出不变。

9.1 官方训练数据与本轮数据的实际差异

Draft/refiner 学的不是抽象的“语言能力”，而是 target model 在具体前缀状态下的条件分布。thinking response 会经过长推理、枚举、回溯和自我修正；non-thinking response 则从不同 chat-template 控制状态开始，更直接地生成答案。即使 user prompt 相同，下面两类监督也不是同一个训练样本：

Thinking：\(p_T(x_{t+1}\mid \text{prompt},\langle think\rangle,x_{1:t})\) Non-thinking：\(p_T(y_{s+1}\mid \text{prompt},y_{1:s},\text{thinking disabled})\)

本轮所有 target hidden states、teacher logits、DFlash hidden 和 refiner 梯度都沿 thinking token 前缀产生；线上却把同一个 head 施加到 non-thinking hidden states。低秩 residual 学到的是“在 thinking 状态分布上如何改写 base logits”，而不是一个保证跨模式成立的普适修正。更不利的是，base DFlash 本身是面向 non-thinking 使用的强 checkpoint；错分布 head 只需把少量 top-1 推离正确 token，就会缩短整轮连续接受前缀。

9.2 为什么 30K 离线更好仍不能消除问题

扩大同一错位分布的数据，只会更精确地拟合 thinking teacher。30K validation 仍从相同 thinking 数据分布切分，所以 loss、top-1 和 EAL proxy 同步改善是合理的；它们没有测试 head 在 non-thinking hidden states 上的行为。这与真实测试四个数据集全部下降并不矛盾。

9.3 仍存在第二层目标错配

数据模式不是唯一待验证因素。CE 与 TV 都在 teacher-forced 的每个位置独立计算；线上收益要求 slot 1 开始连续正确，且本轮 proposal 会改变下一轮 prefix。当前位置衰减鼓励前部位置，但 loss 没有直接计算每个 block 的首错位置，offline EAL 又是 marginal accuracy 的乘积。因此正确结论是：

  1. 当前 thinking→non-thinking 分布错配足以使本轮结果不适合作为结构结论；应先修正数据。
  2. 换成 target-specific non-thinking on-policy 数据后，仍需保留真实 paired acceptance 评测，不能只依据 offline EAL 放大训练。
  3. 若 non-thinking 数据仍出现离线提高、线上下降，再单独比较现有 loss 与 prefix-aware objective，而不是同时改变结构、数据和 loss。

不能简单删除 <think>…</think>。删除文本后的最终答案不是 Qwen3-8B 在 enable_thinking=false 下真实生成的 token 轨迹，也无法恢复对应 hidden states 和 teacher logits。正确修复是从相同 prompts 重新运行 target model，并明确关闭 thinking。

10. 实现核对、已排除问题与限制

10.1 已完成的结构核对

  • 零初始化等价：up_proj=0 时 refined logits 与 base logits 严格一致；关闭 head 直接返回 base logits。
  • Shift 与 block 边界：slot i 只响应同 block 的 hi−1；block 尾部不会影响下一个 anchor；非整 block 输入显式报错。
  • 训练/推理一致：训练从 h0, …, h14 修正 slot 1—15；推理保留完整 16-slot hidden 后执行相同对齐。
  • 冻结有效：初始化与 5K checkpoint 对比，60 个非-refinement tensors 逐元素不变；只有 down/up 两个权重更新。
  • Checkpoint 兼容检查：加载时检查 hidden size、词表、block size、模型类型和 target layer IDs，只允许两个 refiner tensors。
  • Lossless 输出：四数据集共 512 个 prompt 的 base/refined greedy target 输出全部一致，说明 proposal 变化没有破坏 target 输出正确性。

10.2 指标实现修复

早期 distributed 日志中的 base_full_acc 被错误缩小。原因是两个 metric total 共享 tensor，trainer 对每个 metric 原地执行 distributed reduction，导致 rank 0 同一分母被归约两次。修复后每个 counted metric 使用独立 total，trainer 在 reduction 前 clone tensor；正式 step 0 的 refined/base full accuracy 相同，refinement_changed_top1=0。本页表格使用修复后的 validation 文件，不使用早期错误日志。

10.3 当前限制

  1. 正式 acceptance JSON 缺少 refiner checkpoint 路径、git commit 和权重哈希，阶段归因不完整。
  2. 推理使用 Transformers SDPA，不是 vLLM/SGLang 部署路径；每 token 时间只说明当前实现有额外成本。
  3. 四个 benchmark 都是 non-thinking，尚未补做同 checkpoint 的 thinking 测试来直接量化模式内外差异。
  4. 当前 loss 使用 teacher-forced position objective，offline EAL 不是逐 block 真实 prefix length。
  5. 尚未得到 5K target-specific non-thinking 训练结果，因此不能判断同一结构在对齐数据上是否转正。

11. 结论与下一步

  1. 结构与工程链路已跑通：head 只读同 block 前一 hidden，不跨 block，不增加逐 token draft 循环，冻结和训练/推理 shift 均通过核对。
  2. 本轮 thinking 数据上的 offline 指标稳定改善，说明 rank-128 head 有能力拟合 teacher distribution；这不是线上收益证据。
  3. non-thinking 真实生成中，四数据集 acceptance 宏平均下降 3.24%，且额外 projection 增加当前后端耗时；现 checkpoint 不应部署或继续无条件扩大训练。
  4. 训练的 35,000 条 response 全部包含 thinking trace，而测试和官方 Qwen3 DFlash recipe 是 non-thinking。这是当前最明确的分布错配，必须先生成 target-specific non-thinking on-policy 数据。
  5. 下一项受控实验应复用同一组 5,000 个 prompts，只用 Qwen3-8B enable_thinking=false 重新生成 response；保持 base checkpoint、head、seed、训练步数和 loss 不变，再比较 offline 与四数据集 paired acceptance。
  6. 只有 non-thinking 5K 仍出现相同错配时，才进入第二组受控实验：保持数据不变，加入直接面向连续 prefix 的 loss 或真实 block-level checkpoint 选择指标。
