摘要

本页先说明 DFlash、one-pass 前缀树和官方 DDTree 在一次 speculative round 中分别计算什么，再报告相同 Qwen3-8B、相同十个数据集上的结果。one-pass 和 DDTree 都只执行一次 draft forward 与一次 target forward；one-pass 从一份 logits 矩阵中挑选四个高风险位置并复用原 suffix，DDTree 则在每个位置保留 top-K 候选，用 best-first search 填满节点预算。

在十个数据集的完整实验中，我们的 onepass_splice_positions/1 相对本地 single/1 将宏平均 tau 提高 18.76%，decode latency 降低 9.88%。官方 DDTree 的 Qwen3-8B 复现中，B=128 相对官方 DFlash 将宏平均 tau 提高 40.48%，latency 降低 26.23%。两者使用不同树预算、wrapper 和 cache layout，下面同时给出各自的内部对照，不能把两组百分比解释为直接 head-to-head。

1. 实验设置与指标

每一轮从已确认前缀的最后一个 token 作为 anchor，DFlash block-16 再提出最多 15 个 draft token。target 验证候选后，只提交从当前前缀开始连续匹配的路径，并提交一个由 target 产生的 bonus token。所有方法都由完整 target 决定最终输出，因此保持 lossless。

per-sample 与 per-step：per-sample tau 先在每个 prompt 内计算该 prompt 所有 verification rounds 的平均提交长度，再对 prompt 等权平均；per-step（micro）则把所有 rounds 的提交 token 与 round 数直接相除。当前本页从 summary.json 汇总的 one-pass 和官方 DDTree 主表使用 per-step 口径；DARTree 历史 Table 1 使用 per-sample 口径。两种口径都以“每轮提交 token（含 bonus）”为分子，但不能混用。

2. DFlash 基线数据流

DFlash 的 draft forward 不是一个按 token 自回归运行的小模型，而是一个 block 并行网络。它读取已确认 target cache 的最后位置和 target 的中间层 feature，一次产生 15 个位置的 logits。第 i 个位置不会读取同一轮中第 i-1 个位置刚生成的 token。

2.1 主要矩阵计算

拼接C = concat(H(1), H(9), H(17), H(25), H(33)) ∈ R|P|×(5·4096)投影C′ = RMSNorm(C WcT),   Wc ∈ R4096×20480注意力Q = RMSNorm(XWq),   K,V = [C′;X]Wk,vAttention(X,C′) = softmax(QKT/√d)V输出Z = Hdraft WlmT ∈ R15×151936Qwen3-8B 的 hidden size 是 4096，|P| 是已确认前缀长度；矩阵乘法混合 hidden channel，softmax 按每行归一化，RMSNorm、激活和残差是逐元素/按 token 运算。

一次 forward 的输出是整块 logits 矩阵，而不是已经经过 target 验证的 token 序列。因此 baseline 的 acceptance 由 target posterior 决定，而不是由 draft 的 argmax 直接决定。

3. 官方 DDTree 数据流

官方 DDTree 复用同一份 DFlash logits，但把每个位置的概率质量扩展成一棵前缀闭合树。这里 B 是整棵树的 draft 节点预算，不是每层宽度；K 是每层预先保留的 top-K token 候选数。官方实现通常取 K = B，随后 best-first heap 只取联合 log-probability 最高的 B 个节点，所以每层实际节点数不固定。

3.1 树节点分数与 target mask

s(y1:i) = Σj=1…i log softmax(zj)[yj]node = (token, depth, parent),   |nodes| ≤ BMu,v = 0   iff   v ∈ {root(u)} ∪ ancestors(u) ∪ {u};   otherwise −∞Ptarget = softmax(Target([P; tree], M))

target 的 tree attention 并不是把所有节点互相连接：例如 A′ 只能看到 root 和自身，不能看到 B；这样每个分支对应一个独立前缀条件。验证结束后只沿最长匹配路径 gather KV，下一轮重新从真实前缀开始。

4. One-pass 数据流

one-pass 的目标是只支付一次 DFlash forward，却利用 verification budget 提供互补候选。第一轮 logits 先估计主链最可能的首个失败位置，再在四个风险最高的不同位置各取一个非主链 token。与 DDTree 不同，它不枚举每层 top-K 并做联合概率 best-first search；与两轮 risk branch 不同，它也不重新运行第二次 draft。

4.1 分支选择与树构造公式

qi = softmax(zi)[yi]ri = (∏j<i qj)(1 − qi),   I = Top4(r1:15)y′i = argmaxv ≠ yi softmax(zi)[v]pathi = [y1:i−1, y′i, yi+1:15],   i ∈ IT = Trie(path0 = y1:15, pathi),   verify(T) = longest target-matching path

这里的 suffix 是“未条件化”的：它仍由原始 DFlash 主链 logits 产生，并没有看到 y′i。因此 one-pass splice 是一次 forward 成本下的候选覆盖方法；两轮 risk_branch_positions/2 会在每个 alternative 前缀后重新预测 suffix，可以作为质量上界，但 draft 成本约翻倍。

5. 代码实现与验证

实验 runner 位于根仓库 agentWorkSpace/20260818_dflash_multistep_denoising/，DFlash 实现位于 implementations/dflash/dflash/model.py。one-pass 的核心函数是 _first_failure_risk、_select_onepass_branches、_build_onepass_candidate_paths 和 _build_candidate_union_tree；官方 DDTree 复现使用 agentWorkSpace/20260826_ddtree_official_reproduction/upstream/ddtree.py，没有修改作者的树构造和 verifier walk。

  1. baseline 创建 [anchor, MASK×15]，调用一次 draft，直接把 15 个 argmax 组成一条 chain。
  2. one-pass 在同一份 logits 上计算风险、选择 branch，使用 parent/token 去重合并 trie，并生成 ancestor-only 4-D attention mask。
  3. DDTree 对每层 logits 做 top-K 和 log-softmax，在 CPU heap 中扩展到 B 个节点，再把 node depth、parent 和 visibility 拷回 GPU。
  4. target forward 后，baseline 沿 chain 匹配；两种 tree 方法沿 child map 匹配最长路径，并只 compact 被接受路径的 target cache。

例如 GSM8K 的 one-pass：本地 single 为 tau 6.291、7.353 ms/token，splice 为 tau 7.483、6.592 ms/token；因此 tau 变化为 7.483/6.291−1 = +18.95%，latency 变化为 6.592/7.353−1 = −10.36%。官方 DDTree B=128 则使用另一套官方 baseline：tau 6.291→8.690，latency 7.524→5.609。

8. 结论与限制

  1. one-pass splice 已在十个数据集上完成复现；它只增加一次 tree construction，不增加 draft forward，宏平均 tau +18.76%、decode latency −9.88%。
  2. 官方 DDTree B=128 的 acceptance 增益更大，宏平均 tau +40.48%；它使用 128 个节点，target 验证和构树成本也更高，但在当前 SDPA 环境仍取得 −26.23% latency。
  3. one-pass 并不是“第二次 draft 的近似实现”：它不重新预测 alternative suffix，而是复用原主链 suffix；两轮 risk branch 的 tau 更高，但额外 draft 成本使端到端收益明显变小。
  4. one-pass 的四个分支是按首拒绝风险选位置，DDTree 的 B/K 是节点和候选预算。前者偏向少量互补分支，后者偏向概率排序的完整前缀树。
  5. 官方复现当前使用 SDPA fallback，不能把绝对 latency 当作论文 FlashAttention-2 硬件数字；跨方法比较应优先看同一 wrapper 内的相对变化。
