DFlash 后缀复用可行性研究

错误前缀下“当轮判对”的 token，在修正前缀后有多少会再次提出并被接受？

实验时间
2026-08-29
模型
Qwen3-4B / DFlash block-16
数据
7 个数据集，56 条 trace
状态
DFlash 统计与三组 DARTree 探针完成

摘要

结论是不支持无条件复用整段后缀。DFlash（Block Diffusion for Flash Speculative Decoding，块扩散快速推测解码）trace 中，首次错误后的 proposal token 有 30.44% 等于目标模型在错误前缀下的最大概率 token；但要求“下一轮在同一绝对位置再次提出同一个 token，并且它落入连续接受前缀”后，只剩全部后缀的 6.20%，或当轮已判对 token 的 20.35%。DARTree（Diffusion Autoregressive Tree，扩散式自回归草稿树）进一步把旧候选移到真实修正前缀后重新验证，严格匹配边的迁移率只有 15.53%。这些数字说明后缀含有信号，但信号不足以替代正常下一轮。

1. 术语与问题定义

目标模型（target model）是最终决定输出分布的大模型；草稿模型（draft model）先提出候选以减少目标模型调用次数。一个 token 是 tokenizer 划分后的离散符号。一次 proposal 是草稿模型在一轮中提出的候选 token 序列。目标模型只提交从当前位置开始连续匹配的候选；首次不匹配后面的 token 称为本页的后缀。

设已经确认的前缀为 \(P\)，DFlash 一次提出 \(K\) 个 token：

D = (d1, d2, …, dK)

若 \(d_a\) 是首次不匹配 token，本轮只提交 \(d_1,\ldots,d_{a-1}\) 和目标模型给出的补充 token \(b\)，新前缀为 \(P'=(P,d_1,\ldots,d_{a-1},b)\)。旧后缀 \(d_{a+1},\ldots,d_K\) 的目标输出是在包含错误 token \(d_a\) 的条件下计算的：

旧条件：pT(da+1 | P, d<a, da)真实下一轮条件：pT(da+1 | P, d<a, b)

两式的完整因果前缀不同，因此“旧条件下目标模型的最大概率 token”不能直接提交。它至多能作为新一轮候选，仍必须在 \(P'\) 下重新验证。

2. 严格统计事件

不能按数组下标直接比较相邻两轮，因为提交若干 token 后，下一轮 block 的起始位置已经前移。当前轮起点为 \(s\)，后缀 token \(d_j\) 的绝对生成位置是 \(u=s+j\)；下一轮起点为 \(s'\)，所以同一位置在下一轮的数组下标是 \(u-s'\)。

Er,j = 1[dj = argmaxv pT(v | P,d<j)∧ D′u-s′ = dj ∧ 0 ≤ u-s′ < A′]A′ 是下一轮从开头连续接受的 proposal token 数；argmax 表示概率最大的 token。
  1. 当轮目标一致：旧 token 等于目标模型在含错误前缀时的最大概率 token。
  2. 绝对位置相同：先把当前轮下标换成绝对生成位置，再映射到下一轮。
  3. token 相同：下一轮 DFlash 必须再次提出旧 token。
  4. 真正接受：该位置必须落入下一轮从开头连续接受的区间，出现在再次被拒的后缀不计。

首次错误 token 已被补充 token 替换，不属于可回收后缀；没有下一轮可供观察的末轮不进入严格事件分母。

4. DARTree 三阶段因果探针

DFlash trace 是自然观察：下一轮是否碰巧再次提出旧 token。DARTree 探针则显式构造旧后缀候选，把它接到目标模型实际提交的补充 token 后，再用正确的 target KV cache 重新验证。三个阶段逐步排除不合法的信息复用。

A. 朴素拒绝状态回收读取被拒分支的目标预测并聚合成候选树。不同节点可能来自不同错误前缀，只作为激进上界，不作为安全算法。
B. 补充 token 重置修正先把真实补充 token 输入 Domino 的门控循环单元，再消费旧 block 尚未使用的并行 hidden state。相对同长度 fresh rerun 保留 72.09%，但相对完整下一轮只保留 32.03%。
C. 严格连续匹配边回收只保留旧树中真实存在、且目标模型在该错误父前缀下确实选择的边；第一条不匹配立即停止，然后在真实前缀下重验。

4.1 严格构树规则

对旧树节点 \(v\)，只有当其 token 正好等于目标模型在父节点完整路径 \(\pi(parent(v))\) 下的最大概率 token，才保留这条真实边：

token(v) = argmaxy pT(y | π(parent(v)))
for 每个首次错误 token 下的旧树分支:
    current = 错误子节点
    while 目标模型在 current 后的 argmax
          恰好等于旧树的一条真实子边:
        把这条边加入回收树
        current = 该真实子节点
    # 第一条不匹配立即停止

算法不根据目标预测凭空新增旧树不存在的边，也不跳过中间不匹配边。候选树构建后，target KV cache 先收缩到真实接受路径；探针在缓存副本上验证，因此不会改变正式生成输出或污染下一轮。

5. 严格回收示例

真实前缀为 P，目标模型在首次错误处给出补充 token b

旧错误路径：P → x → a → c → d
旧 target：    x 后预测 a      ✓ 旧树中存在 x→a
               x,a 后预测 c    ✓ 旧树中存在 a→c
               x,a,c 后预测 e  ✗ e ≠ d，立即停止

回收候选：P → b → a → c
验证方式：必须在 P→b 的正确 KV cache 上重新运行目标模型

旧路径上的 \(a,c\) 只证明它们在 \(P,x\) 开头的错误条件下连续正确。把 \(x\) 替换成真实补充 token \(b\) 后，注意力读到的所有后续键和值都发生变化，所以 \(a,c\) 仍只是 proposal，不是已接受输出。15.53% 的迁移率正是测量这种完整条件变化。

7. 结论与下一步

  1. 错误前缀下 target-correct 的后缀不是零，但下一轮严格重新接受只占全部后缀 6.20%；不能把 30.44% 当作可直接复用率。
  2. 严格 DARTree 探针把旧边移到真实前缀后，只有 15.53% 继续匹配，说明主要损失来自因果前缀改变，而不只是下一轮 DFlash 没有再次提出。
  3. 无条件用回收树替代正常下一轮的单位时间接受量估计下降 19.15%；即使假设全部迁移且每轮能完美选择，理想上限也只有 +3.34%。
  4. 若继续研究，合理形式是把旧后缀作为正常新 proposal tree 的少量附加分支，按距首次错误的位置、连续匹配长度、目标/草稿置信度和任务域分配预算；所有分支仍在修正后的真实前缀上由目标模型验证。

术语补充

target-correct 指 token 等于目标模型在该位置的最大概率 token；trace 指逐轮结构化运行记录；block-16 指一个锚点加最多 15 个新 proposal 位置；SDPA 是 scaled dot-product attention（缩放点积注意力）；sample-bootstrap 是按完整样本重采样、保留样本内多轮相关性的置信区间方法；Domino 是 DARTree 的顺序修正模型，其核心状态更新器是门控循环单元（Gated Recurrent Unit，GRU）；fresh rerun 指从真实前缀正常重算同样长度的下一轮候选。
