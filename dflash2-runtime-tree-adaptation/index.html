4. C：同前缀诊断与在线可预测性

计划选 HumanEval、GSM8K、MT-Bench 各16条，在已生成32、96、192个token处取得可用检查点。保存实际prompt和生成token IDs，验证精确前缀、状态恢复及重复回放一致性；EOS不足检查点单独记录。

比较全局固定配置、任务固定配置与逐前缀事后选择；记录接受长度、失败深度、候选覆盖、离开trunk的位置，以及draft、builder、target、commit成本。相同长draft候选的深度截断作为单独的形态诊断。

验证前特征包括selector分差、熵、累计路径分数、历史接受长度和失败深度、上下文长度及历史step时间。按请求划分训练和测试，并做留一任务检查。局部oracle是诊断上限；若潜力仅约1%—2%或不超过噪声和控制开销，则不增加复杂在线控制器。有明确潜力时，再以简单档位选择器进行真实E2E对照。

5. 指标、验收和资源管理

  • 主吞吐为实际 completion tokens 总和除以 client wall 总和，排除加载与预热；另报排除metrics请求的HTTP请求延迟口径。
  • 同时报告请求平均tau与按验证步汇总tau。原始tau=1+accepted draft/验证步数；停止条件在接受计数之后截断输出，故另报实际输出/验证步数和去掉末步的接受长度分布。
  • A各方法都开启scheduler request trace，关闭selector trace。后者会给chain增加CPU构树与拷贝成本，其诊断计时与正式E2E分开。
  • 短smoke中，chain block24和两种tree各有1/2条输出与chain block16不完全相同。已保留差异，同前缀定位和任务质量评估待完成；计数审计与模型正确性验收分别报告。
  • 每个完成点先核对请求参数与scheduler计数，数据checksum变化时拒绝复用。预检v1的容器长度统计错误已标记无效，正式运行仅接受正确提取input_ids的v2。
  • 实验使用同一GPU排他锁，只释放完整命令行匹配的已知占位程序，结束、异常或信号退出后恢复并验证。未知GPU进程不作清理。
