摘要

本页只讨论 DFlash2 风格的 path selector：它不生成词表外的新 token，而是在 DFlash 每个 proposal 槽位的 top-K 候选中重新选择一条连贯路径。selector 的可训练参数是隐藏状态投影、前驱 token codebook 和后继 token codebook；Qwen3-8B target 与原始 DFlash backbone 始终冻结。

最重要的有效版本是 5k non-thinking、lr=1e-4、纯 teacher forcing 的 top-K=64 训练，以及其 30k、1 epoch 扩展。前者在 GSM8K 512 条 paired full-round 评测中每轮 target 接受长度增加 0.0481 token，并在 GSM8K、MATH-500、MBPP、HumanEval、MT-Bench 上方向为正；后者在 7 个数据集、每集最多 128 条的评测中全部为正，GSM8K 增加 0.2802、MATH-500 增加 0.2683 个 target 接受 draft token。当前 30k×5 epoch run 尚未完成，不能提前把这些数字归因于新 epoch。

“接受长度”统一指一次 verification round 中 target 实际接受的连续 draft token 数，不包含 target bonus token；它不是最终答案准确率，也不是离线 validation loss。

2. 术语与实验边界

Target model 是 Qwen3-8B，负责给出验证标准；DFlash backbone 是已训练好的 block-diffusion draft transformer，一次并行产生一个 block；anchor 是上一轮已经被 target 确认的 token，占 block 的 slot 0；proposal 是需要 target 验证的后续 token，block-16 中共有 15 个 proposal 槽位。

Logit 是 softmax 之前对词表每个 token 的分数；top-k candidate 是某槽位分数最高的 K 个 draft token；unary score 是候选自身的原始 DFlash logit；edge score 是“给定前驱后选择当前候选”的分数。Teacher forcing 在训练时使用真实 target 前驱；推理时则使用 path walk 上一槽位实际选出的候选前驱。

本实验不把“离线 candidate coverage”误称为接受率。coverage 只回答 target token 是否在候选集合内；只有 full-round speculative decoding 才能回答连续前缀实际被 target 接受了多少 token。

3. 官方一致的推理数据流

3.1 一次 DFlash forward 的输入和输出

在 DFlashDraftModel._backbone_forward 中，已确认序列的 token 位置被选为 anchor。对每个 anchor，代码构造长度为 B=16 的输入：

\(x^{\mathrm{draft}}=[a,\mathrm{MASK},\mathrm{MASK},\ldots,\mathrm{MASK}]\in\mathbb{N}^{16}\) \(H^{\mathrm{draft}}\in\mathbb{R}^{NB\times D},\quad Z^{\mathrm{base}}=\operatorname{LMHead}(H^{\mathrm{draft}})\in\mathbb{R}^{NB\times V_d}\)

这里 N 是一次 packed forward 中的 anchor block 数，D=4096 是 DFlash hidden size，Vd=151936 是 draft vocabulary。代码 reshape 成 [N,16,D] 和 [N,16,Vd]，舍弃 slot 0 的 anchor 输出，只把 slot 1—15 作为 proposal：

\(H=H^{\mathrm{draft}}_{1:16}\in\mathbb{R}^{N\times15\times D},\quad Z=Z^{\mathrm{base}}_{1:16}\in\mathbb{R}^{N\times15\times V_d}\)

若把完整 16 个 hidden 当作 proposal，slot 0 的 anchor hidden 会错位地监督第一个 token，训练和推理就不是同一个问题。

3.2 候选和前驱行

对每个 proposal slot s，CandidatePathSelector.topk 保留分数最高的 K=64 个 token：

\(C=\operatorname{TopK}(Z)\in\mathbb{N}^{N\times15\times64},\quad U=\operatorname{TopKValues}(Z)\in\mathbb{R}^{N\times15\times64}\)

DFlashSelectorDraftModel._predecessor_ids 构造相邻候选图：slot 0 的 64 行全部使用同一个 anchor；slot s>0 使用 slot s−1 的 64 个候选。

\(P_{0,p}=a\ (p=1,\ldots,K),\quad P_{s,p}=C_{s-1,p}\ (s>0)\) \(P\in\mathbb{N}^{N\times15\times64}\)

3.3 边分数与 path walk

selector 的三个参数是隐藏投影 \(W_h\in\mathbb{R}^{R\times D}\)、前驱 codebook \(A\in\mathbb{R}^{V_p\times R}\)、后继 codebook \(B\in\mathbb{R}^{V_d\times R}\)，本实验 R=16：

\(Q_{n,s,:}=W_hH_{n,s,:}\in\mathbb{R}^{R}\) \(E_{n,s,p,q}=U_{n,s,q}+\sum_{r=1}^{R}A_{P_{n,s,p},r}\,Q_{n,s,r}\,B_{C_{n,s,q},r}\) \(E\in\mathbb{R}^{N\times15\times64\times64}\)

边打分是一次并行 tensor contraction；之后 CandidatePathSelector.walk_path 按 slot 左到右做很小的 argmax：第一个 slot 从 anchor 行选候选，下一 slot 使用刚选出的候选索引作为 predecessor row。

\(\hat q_0=\arg\max_q E_{0,0,0,q}\) \(\hat q_s=\arg\max_q E_{0,s,\hat q_{s-1},q},\quad \hat y_s=C_{s,\hat q_s}\)

推理总流程是：一次 DFlash forward → 一次 LM head → 一次 selector edge scoring → 15 步小型 path walk → target verification。串行只存在于最后的索引选择，不是重新运行模型。

4. Speculators 训练数据流

  1. 预处理。scripts/prepare_data.py 把 30k JSONL 对话编码为 token 序列、assistant loss mask、document id 和 position id；当前数据是 non-thinking 轨迹。
  2. target hidden-state online server。GPU0 上冻结的 Qwen3-8B vLLM 服务按 batch 产生指定层 hidden states。launcher 指定 target layer ids 1 9 17 25 33，供 DFlash context feature 使用。
  3. anchor block 构造。_backbone_forward 抽取 anchor；每个 anchor 形成 16 槽块，slot 0 写真实 anchor，其他槽位写 mask token。
  4. 冻结 DFlash forward。target context hidden 经过 DFlash 输入投影和归一化；DFlash layers 使用 anchored-block attention mask，一次输出所有 block hidden、base logits 和对齐后的 target labels。
  5. 去掉 anchor。代码将结果 reshape 成 [batch × num_blocks, 15, ...]，得到 hidden_paths、logits_paths、target_paths；slot 0 loss mask 已在 backbone 中清零。
  6. 两套 predecessor 视图。完整 graph 的 predecessor rows \(P\) 用于推理一致的 edge scores；当前 loss 使用 teacher-forced predecessor \(P^{\mathrm{TF}}=[a,y_1,\ldots,y_{14}]\)，其中 \(y_s\) 是 target 的第 s 个 proposal token。
  7. 只更新 selector。selector_freeze_dflash_backbone=True 使只有三个 selector 参数张量有梯度；checkpoint 也只保存这三组张量，加载时从官方 DFlash checkpoint 重建 backbone。

5. Loss 与训练指标

5.1 当前有效版本的 teacher-forced loss

每个 slot 使用一个明确的真实 target 前驱，而不是把同一个 target 复制到所有 predecessor row。先计算：

\(S^{\mathrm{TF}}_{n,s,q}=U_{n,s,q}+\sum_{r=1}^{R}A_{P^{\mathrm{TF}}_{n,s},r}\,Q_{n,s,r}\,B_{C_{n,s,q},r}\) \(S^{\mathrm{TF}}\in\mathbb{R}^{N\times15\times64}\)

若 target token \(y_{n,s}\) 在候选集合 \(C_{n,s,:}\) 中，令其候选排名为 \(r_{n,s}\)，对有效位置集合 \(\mathcal{V}\) 计算：

\(\ell_{n,s}=-\log\frac{\exp S^{\mathrm{TF}}_{n,s,r_{n,s}}}{\sum_{q=1}^{64}\exp S^{\mathrm{TF}}_{n,s,q}}\) \(w_s=0.8^{s},\qquad \mathcal{L}=\frac{\sum_{(n,s)\in\mathcal{V}}w_s\ell_{n,s}}{\sum_{(n,s)\in\mathcal{V}}w_s}\)

_teacher_forced_selector_loss 先生成 present mask，再只对 present 位置取 CE；位置权重是 selector_position_decay ** slot_positions。前部 slot 权重更高，因为第一个错误会截断后续连续接受；这仍是 surrogate objective，不是直接优化真实 EAL。

5.2 被淘汰的 all-predecessor loss

早期版本使用完整 \(E\in\mathbb{R}^{N\times15\times64\times64}\)，把同一个 target rank 沿 predecessor 轴复制 64 次：

\(\mathcal{L}_{\mathrm{all}}=\frac{1}{|\mathcal{V}|K}\sum_{(n,s)\in\mathcal{V}}\sum_{p=1}^{K}w_s\,\operatorname{CE}(E_{n,s,p,:},r_{n,s})\)

这相当于监督“无论前驱是什么，都应该选同一个 target”，比推理时的单一路径条件更强，也把不同前驱条件混成了一个标签。30k all-predecessor 版本真实收益混合且不稳定，因此当前改为每个 slot 一个 teacher predecessor。

5.3 初始化、覆盖和最终指标

successor_codebook 严格零初始化，因此：

\(B=0\Longrightarrow E_{n,s,p,q}=U_{n,s,q}\)

未训练 selector 的 path 与冻结 DFlash top-1 相同。训练还记录 candidate coverage、teacher accuracy、base accuracy、fixed-base-error（base 错而 selector 对）和 regressed-base-correct（base 对而 selector 错）。

最终入口是 eval_final_acceptance.py。baseline 和 selector 分别推进自己的多轮 context，每轮连续接受 \(m_r\) 个 proposal；核心字段是 mean_target_accepted_draft_tokens_per_round：

\(\mathrm{EAL}_{\mathrm{round}}=\frac{1}{R}\sum_{r=1}^{R}m_r,\qquad m_r=\max\{j:\hat y_{r,1:j}=y^{\mathrm{target}}_{r,1:j}\}\)

mean_committed_tokens 约等于 \(m+1\)，包含 target 在拒绝位置产生的 bonus token；本页核心表格均使用不含 bonus 的 EAL。

6.1 早期 top-k 数值：为什么只作诊断

早期 standalone 脚本在严格 held-out 区间观察到明显的候选覆盖效应：第 3500–4499 条样本上，top-k=24 的旧单块 EAL 为 0.95（相对 base +0.901，coverage 0.670），top-k=32 为 1.16（+1.111，0.724），top-k=48 为 1.481（+1.432，0.786），top-k=64 为 1.575（+1.526，0.821）；第 4000–4999 条中 top-k=64 为 1.551（+1.496，0.812）。这些数字说明候选集合越大，target token 越容易落入可重排集合，但它们使用了旧的单块 evaluator，且部分运行在 anchor/slot 对齐修复之前。因此它们只能支持“candidate coverage 是上限”这一诊断，不能和当前 full-round EAL 直接比较。

对齐修复后使用 lr=0.01 的 5k 训练也不应作为正负收益基线：top-k=16 在 GSM8K 128 条上从 base 3.26520 降到 1.54333，top-k=64 降到 1.92212；训练日志同时显示后段 loss 上升。该实验的价值是隔离出高学习率和首 slot 回退问题，而不是证明 selector 结构不可行。

8. 结论与限制

  1. 当前最可信的正收益不是早期高 EAL 数字，而是 anchor 对齐后、top-k=64、lr=1e-4、teacher-forced loss、full-round evaluator 得到的结果。
  2. top-k 决定候选覆盖上限；候选多不等于路径排序正确。早期 top-k 实验主要用于证明候选覆盖瓶颈。
  3. teacher-forced loss 的关键是每个 slot 只在一个明确的 target predecessor 条件下监督一个候选排名；all-predecessor loss 把多个不同条件混成了同一标签。
  4. 位置衰减 \(0.8^s\) 体现前部接受的重要性，但它仍是 surrogate objective；最终必须检查每轮 target accepted draft tokens，以及 fixed/regressed 诊断。
  5. 5 epoch 可能继续降低训练 loss，也可能在训练轨迹上过拟合并损害真实 path walk。只有 output/0–4 都评测后，才能判断最佳 epoch。

当前 5-epoch run 尚未完成，页面中的 5-epoch 行只记录配置和状态。后续评测脚本会分别输出每个 epoch 的 candidate coverage、首 slot acceptance、全 round EAL、fixed-base-error 和 regressed-base-correct。
