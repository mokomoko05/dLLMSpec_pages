摘要

DFlash2 风格的 path selector 只在每个 proposal 槽位的 top-K 候选里重选一条路径。可训练参数是隐藏状态投影、前驱 codebook 和后继 codebook；Qwen3-8B target 与 DFlash backbone 始终冻结。

有效训练配方是 30k non-thinking、top-K=64、lr=1e-4、纯 teacher forcing。独立跑完 5 个 epoch 后，把它接到官方 dflash_generate 循环里评测：GSM8K、MATH-500、MBPP、HumanEval、AIME25 × epoch 0–4，共 25 点。2710/2710 条样本的 target greedy 输出与 baseline 完全一致；五数据集等权的 per-sample accepted draft 平均值从 base 5.9917 提升到 epoch 4 的 6.2543，增量 +0.2625。AIME25 epoch 0 为 −0.0122，其余 24 点为正。

接受长度指一轮 verification 中 target 连续接受的 draft token 数，不含 bonus。第 7 节的离线 full-round 表用来筛选上述配方；第 8 节的在线表才是与官方解码循环一致的结论。两套数字因首轮 anchor / KV cache 不同，分开读。

2. 术语与实验边界

Target model 是 Qwen3-8B，负责给出验证标准；DFlash backbone 是已训练好的 block-diffusion draft transformer，一次并行产生一个 block；anchor 是上一轮已经被 target 确认的 token，占 block 的 slot 0；proposal 是需要 target 验证的后续 token，block-16 中共有 15 个 proposal 槽位。

Logit 是 softmax 之前对词表每个 token 的分数；top-k candidate 是某槽位分数最高的 K 个 draft token；unary score 是候选自身的原始 DFlash logit；edge score 是“给定前驱后选择当前候选”的分数。Teacher forcing 在训练时使用真实 target 前驱；推理时则使用 path walk 上一槽位实际选出的候选前驱。

本页把 candidate coverage 定义为 target token 落入候选集合的比例，把 接受长度 定义为 full-round speculative decoding 中 target 实际接受的连续 draft 前缀长度。前者衡量候选上限，后者衡量端到端路径效率。

3. 官方一致的推理数据流

3.1 先固定符号和索引

下面统一使用数学中的1-based 索引；代码里的 0-based 下标对应减一。令 \(N\) 为本次 packed forward 展平后的 anchor block 数，\(B=16\) 为 block 长度，\(S=B-1=15\) 为 proposal 槽位数，\(K=64\) 为每个槽位保留的候选数，\(D=4096\) 为 hidden size，\(d_r=16\) 为 selector 低秩维度。\(V_t\) 与 \(V_d\) 分别是 target/verifier 与 draft 词表大小。前驱 codebook 的行属于 \(V_t\)，后继 codebook 和候选 token 属于 \(V_d\)。本页实验没有启用词表裁剪，因此 \(V_t=V_d=151936\)。

索引含义：\(n\in\{1,\ldots,N\}\) 是 block，\(s\in\{1,\ldots,S\}\) 是 proposal slot，\(p,q\in\{1,\ldots,K\}\) 分别是前驱行和当前候选列，\(r\in\{1,\ldots,d_r\}\) 是低秩分量。后文用 \(G\) 表示后继 codebook，避免和 block 长度 \(B\) 重名；用 \(T\) 表示 verification round 数，避免和低秩维度混用同一个 \(R\)。

3.2 一次 DFlash forward 的输入和输出

在 DFlashDraftModel._backbone_forward 中，已确认序列的 token 位置被选为 anchor。对每个 anchor，代码构造长度为 \(B=16\) 的输入：第 1 位写真实 anchor，其余 15 位写 MASK。

\(x^{\mathrm{draft}}_n=[a_n,\mathrm{MASK},\ldots,\mathrm{MASK}]\) \(H^{\mathrm{draft}}\in\mathbb{R}^{N\times B\times D},\quad Z^{\mathrm{base}}=\operatorname{LMHead}(H^{\mathrm{draft}})\in\mathbb{R}^{N\times B\times V_d}\)

其中 \(a_n\) 是第 \(n\) 个 block 的 anchor。DFlash 的 LM head 输出 draft logits。完整块的 1-based 下标是 \(1,\ldots,B\)，第 1 位是 anchor。丢掉该位后，proposal 重新编号为 \(s=1,\ldots,S\)，对应原下标 \(s+1\)：

\(H_{n,s,:}=H^{\mathrm{draft}}_{n,s+1,:}\in\mathbb{R}^{D},\quad Z_{n,s,:}=Z^{\mathrm{base}}_{n,s+1,:}\in\mathbb{R}^{V_d}\)

这与代码 [:,:,1:] 丢掉 0-based 第 0 位一致。Python 切片 [1:16] 取出 15 个 proposal；数学记号对应这 15 个位置。完整 16 个 hidden 若整体作为 proposal，会让 anchor hidden 错位监督第一个 token，训练和推理的目标随之分离。

3.3 候选和前驱行

对每个 proposal slot \(s\)，CandidatePathSelector.topk 同时返回候选 token ID 和对应的原始 DFlash logit：

\((C,U)=\operatorname{TopK}_K(Z),\quad C\in\mathbb{N}^{N\times S\times K},\quad U\in\mathbb{R}^{N\times S\times K}\)

前驱行矩阵 \(P\) 直接存储 token ID。第一个 proposal 的 \(K\) 行都复制 anchor；之后每个 slot 的第 \(p\) 行对应上一 slot 的第 \(p\) 个候选：

\(P_{n,1,p}=a_n,\qquad P_{n,s,p}=C_{n,s-1,p}\quad(s=2,\ldots,S)\) \(P\in\mathbb{N}^{N\times S\times K}\)

代码在存在 d2t 时会对上一槽位的 draft id 做 draft-to-target 映射再查前驱 codebook；本页实验未启用词表裁剪，该映射是恒等，\(V_t=V_d\)。

3.4 边分数与 path walk

path scorer 的三个参数是隐藏投影 \(W_h\in\mathbb{R}^{d_r\times D}\)、前驱 codebook \(A\in\mathbb{R}^{V_t\times d_r}\)、后继 codebook \(G\in\mathbb{R}^{V_d\times d_r}\)。记 \(Q_{n,s,:}=W_h H_{n,s,:}\)，则相邻候选对的分数为：

\(Q_{n,s,:}=W_h H_{n,s,:}\in\mathbb{R}^{d_r}\) \(E_{n,s,p,q}=U_{n,s,q}+\sum_{r=1}^{d_r}A_{P_{n,s,p},r}\,Q_{n,s,r}\,G_{C_{n,s,q},r}\) \(E\in\mathbb{R}^{N\times S\times K\times K}\)

这与官方 DFlash2 的 \(S_s(a,b)=U_s(b)+\langle A(a)\odot Q(h_s),G(b)\rangle\) 是同一低秩双线性形式；这里把官方后继 codebook \(B\) 写成 \(G\)，避免和 block 长度 \(B\) 重名。\(E\) 是用于候选排序的 logit-like score。边打分一次并行完成，之后 walk_path 按 slot 从左到右做 argmax。第一个 slot 的 \(K\) 个前驱行都是同一个 anchor，因此从第 1 行出发即可：

\(\hat q_{n,1}=\arg\max_{q\in\{1,\ldots,K\}}E_{n,1,1,q},\quad \hat y_{n,1}=C_{n,1,\hat q_{n,1}}\) \(\hat q_{n,s}=\arg\max_{q\in\{1,\ldots,K\}}E_{n,s,\hat q_{n,s-1},q},\quad \hat y_{n,s}=C_{n,s,\hat q_{n,s}}\quad(s=2,\ldots,S)\)

推理总流程是：一次 DFlash forward → 一次 LM head → 一次 selector edge scoring → \(S=15\) 步小型 path walk → target verification。串行部分集中在最后的轻量索引选择，模型前向保持一次。

4. Speculators 训练数据流

  1. 预处理。scripts/prepare_data.py 把 30k JSONL 对话编码为 token 序列、assistant loss mask、document id 和 position id；当前数据是 non-thinking 轨迹。
  2. target hidden-state online server。GPU0 上冻结的 Qwen3-8B vLLM 服务按 batch 产生指定层 hidden states。launcher 指定 target layer ids 1 9 17 25 33，供 DFlash context feature 使用。
  3. anchor block 构造。_backbone_forward 抽取 anchor；每个 anchor 形成 16 槽块，第 1 位写真实 anchor，其他槽位写 mask token。
  4. 冻结 DFlash forward。target context hidden 经过 DFlash 输入投影和归一化；DFlash layers 使用 anchored-block attention mask，一次输出所有 block hidden、base logits 和对齐后的 target labels。
  5. 去掉 anchor。代码将结果 reshape 成 [batch × num_blocks, 15, ...]，得到 hidden_paths、logits_paths、target_paths；slot 0 的 loss mask 已在 backbone 中清零。
  6. 两套 predecessor 视图。完整 graph 的 predecessor rows \(P\) 用于推理一致的 edge scores；teacher-forced predecessor 定义为 \(P^{\mathrm{TF}}_{n,1}=a_n\)、\(P^{\mathrm{TF}}_{n,s}=y_{n,s-1}\)（\(s\ge 2\)），其中 \(y_{n,s}\) 是 target/verifier 在第 \(s\) 个 proposal 上的 greedy label。本页实验 \(V_t=V_d\)，训练代码不额外做 d2t。
  7. 只更新 selector。selector_freeze_dflash_backbone=True 使只有三个 selector 参数张量有梯度；checkpoint 也只保存这三组张量，加载时从官方 DFlash checkpoint 重建 backbone。本页报告的 30k 训练只更新这三个张量。

5. Loss 与训练指标

5.1 当前有效版本的 teacher-forced loss

每个 slot 使用一个明确的真实 target 前驱，并在对应 predecessor row 上监督候选排名。令 \(y_{n,s}\) 为 target label，teacher-forced 分数为：

\(S^{\mathrm{TF}}_{n,s,q}=U_{n,s,q}+\sum_{r=1}^{d_r}A_{P^{\mathrm{TF}}_{n,s},r}\,Q_{n,s,r}\,G_{C_{n,s,q},r}\) \(S^{\mathrm{TF}}\in\mathbb{R}^{N\times S\times K}\)

定义覆盖指示 \(\pi_{n,s}=\mathbf{1}[y_{n,s}\in C_{n,s,:}]\)。若 \(\pi_{n,s}=1\)，令 \(r_{n,s}\) 为满足 \(C_{n,s,r_{n,s}}=y_{n,s}\) 的候选列。训练还使用 proposal mask \(m_{n,s}\)。本页 30k 训练的有效位置是 mask 为真且 target 落在 top-\(K\) 内的格子，不会因为更早 slot 未被覆盖而截断后续 loss：

\(\mathcal{V}=\{(n,s):m_{n,s}=1,\ \pi_{n,s}=1\}\)

于是加权交叉熵为：

\(\ell_{n,s}=-\log\frac{\exp S^{\mathrm{TF}}_{n,s,r_{n,s}}}{\sum_{q=1}^{K}\exp S^{\mathrm{TF}}_{n,s,q}}\) \(w_s=\lambda^{s-1},\ \lambda=0.8,\qquad \mathcal{L}_{\mathrm{TF}}=\frac{\sum_{(n,s)\in\mathcal{V}}w_s\ell_{n,s}}{\sum_{(n,s)\in\mathcal{V}}w_s}\)

_teacher_forced_selector_loss 对 \(\mathcal{V}\) 取 CE。代码 selector_position_decay ** slot_positions 里 slot_positions = arange(S) 是 0-based 的 \(0,\ldots,14\)，因此对应这里的 \(\lambda^{s-1}\)。第一个 proposal 的权重为 1，随后按 0.8 逐槽衰减。前部 slot 权重更高，因为第一个错误会截断后续连续接受；真实 EAL 由完整解码评测给出。

5.2 被淘汰的 all-predecessor loss

早期版本使用完整 \(E\in\mathbb{R}^{N\times S\times K\times K}\)，把同一个 target rank 沿 predecessor 轴复制 \(K\) 次。代码按位置权重对所有前驱行求和再归一化：

\(\mathcal{L}_{\mathrm{all}}=\frac{\sum_{(n,s)\in\mathcal{V}}w_s\sum_{p=1}^{K}\operatorname{CE}(E_{n,s,p,:},r_{n,s})}{K\sum_{(n,s)\in\mathcal{V}}w_s}\)

这相当于监督“无论前驱是什么，都应该选同一个 target”，比推理时的单一路径条件更强，也把不同前驱条件混成了一个标签。30k all-predecessor 版本真实收益混合且不稳定，因此当前改为每个 slot 一个 teacher predecessor。

5.3 初始化、覆盖和最终指标

successor_codebook（本文记为 \(G\)）严格零初始化，因此 path scorer 初始时：

\(G=0\Longrightarrow E_{n,s,p,q}=U_{n,s,q}\)

于是未训练 selector 的 path 与冻结 DFlash top-1 一致。训练还记录 candidate coverage、teacher accuracy、base accuracy、fixed-base-error（base 错而 selector 对）和 regressed-base-correct（base 对而 selector 错）。

最终入口是 eval_final_acceptance.py。baseline 和 selector 分别推进自己的多轮 context，每轮连续接受 \(m_t\) 个 proposal；核心字段是 mean_target_accepted_draft_tokens_per_round。若首个 proposal 就不匹配，则 \(m_t=0\)：

\(\mathrm{EAL}_{\mathrm{round}}=\frac{1}{T}\sum_{t=1}^{T}m_t,\qquad m_t=\max\bigl(\{0\}\cup\{j:\hat y_{t,1:j}=y^{\mathrm{target}}_{t,1:j}\}\bigr)\)

mean_committed_tokens 通常等于 \(m+1\)，因为它还包含 target 在拒绝位置产生的 bonus token；本页核心表格均使用不含 bonus 的 EAL。

6.1 早期 top-k 数值：为什么只作诊断

早期 standalone 脚本在严格 held-out 区间上，旧单块 EAL 随 top-k 上升：第 3500–4499 条里 top-k=24 为 0.95（相对 base +0.901，coverage 0.670），top-k=32 为 1.16（+1.111，0.724），top-k=48 为 1.481（+1.432，0.786），top-k=64 为 1.575（+1.526，0.821）；第 4000–4999 条中 top-k=64 为 1.551（+1.496，0.812）。结论只有一条：候选集合越大，target token 越容易落入可重排范围。这些运行使用旧单块 evaluator，部分还在 anchor/slot 对齐修复之前，数字只用于覆盖诊断。

对齐修复后 lr=0.01 的 5k 训练会打坏首 slot：GSM8K 128 条上 top-k=16 从 base 3.26520 降到 1.54333，top-k=64 降到 1.92212，训练后段 loss 上升。有效配方把学习率降到 1e-4。

8. 官方在线评测

8.1 在线与离线评测流程

离线评测从固定 prompt 和预先组织的 target context 出发，在本地 full-round simulator 中分别推进 baseline 与 selector；每轮执行 DFlash proposal、selector path walk、target greedy verification 和 context 更新。它运行快、覆盖七个数据集，承担配方筛选与逐 epoch 趋势分析。首轮 anchor 直接取 prompt 末 token，KV cache 由 simulator 组织，因此第 7 节保留为训练开发口径。

在线评测复用官方 dflash_generate 的 prefill、DynamicCache、block verification、cache crop 和 EOS 流程。target 先产生首个生成 token 作为 anchor，随后 baseline 与 selector 各自完整解码；selector 只替换 proposal callback。每条样本核对两条路径的 target greedy token 序列，并计算该样本各 verification round 的 accepted draft 平均值，再对样本等权平均。这个流程与部署时的生成循环一致，因此表 7 作为正式结果。

正式矩阵使用 Qwen3-8B / Qwen3-8B-DFlash-b16、BF16、SDPA、block size 16、temperature 0、最多 2048 new tokens；GSM8K、MATH-500、MBPP、HumanEval 每点 128 条，AIME25 每点 30 条。五个 checkpoint 共 25 点，全部运行于单张 A100 80GB。

9. 结论

  1. 正式收益来自官方在线生成循环：top-k=64、lr=1e-4、teacher-forced 30k×5 的 per-sample 汇总持续高于 base，epoch 3 达到 +0.2634 token/round，并保持 2710/2710 输出一致。
  2. top-k 决定候选覆盖上限，selector 学习在候选集合内选择连贯路径；早期 top-k 实验刻画了这一覆盖瓶颈。
  3. teacher-forced loss 的关键是每个 slot 只在一个明确的 target predecessor 条件下监督一个候选排名；all-predecessor loss 把多个不同条件混成了同一标签。
  4. 位置衰减 \(0.8^{s-1}\)（首个 proposal 权重为 1）体现前部接受的重要性，但它仍是 surrogate objective；最终必须检查每轮 target accepted draft tokens，以及 fixed/regressed 诊断。
  5. per-sample 汇总在 epoch 3 达到最高增量 +0.2634；部署候选可按目标数据集选择 epoch 3 或 epoch 4。

80k 数据已生成并通过 80,000 行唯一键校验；selector 训练尚未启动。后续修复 launcher 后，80k 训练与本页 30k×5 结果分别报告，数据采集阶段单独作为数据资产记录。
