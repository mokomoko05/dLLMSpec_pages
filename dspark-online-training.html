ONLINE ≠ 更新大模型

这里的 “online” 指训练 draft model 时，按需从正在运行的 Qwen3-8B verifier 生成目标 hidden states。Verifier 权重始终冻结；被优化的只有 DSpark draft model。

ONLINE PIPELINE

Hidden states 如何流过四张 GPU

训练和 serving 是两个闭环：前者学习 draft，后者才测量 speculative decoding 真正接受了多少 token。

WHERE THE TIME GOES

Hidden-state fetch 是 5K pilot 的主要等待项

稳态单步 4.1–4.5 秒，其中在线 fetch 占 42%–54%。30K 实验在相同角色分工下稳定到约 2.7–3.3 秒/step；首步因编译耗时 30 秒。

WHAT BROKE FIRST

真正花时间的，是把隐含假设逐个显式化

这些失败不是旁枝：它们定义了当前环境中可复现的在线训练与评测配置。

CLI

vLLM 参数版本漂移

--disable-log-requests 在当前 vLLM 版本不受支持，删除后继续。

LINKER

FlashInfer 找不到 -lcuda

直接调用环境 Python 绕过 activation hook；显式补全 library path 与 preload。

ATTENTION

FlexAttention 无可用 kernel

PyTorch 2.11 / A100 上触发 NoValidChoicesError；draft attention 固定为 SDPA。

LENGTH

4096 不是服务端的 4096

completion 还会请求 1 个 token，因此训练序列 4096 时，vLLM 上限必须设为 4097。

CONFIG

V1 需要嵌套 mask 配置

dflash_config.mask_token_id 缺失后补齐，但这还不是最终问题。

RUNNER

DSpark 被误路由为 Eagle

V1 runner 访问不存在的 mask_hidden；真实评测最终固定使用 vLLM V2 runner。

TAKEAWAYS

下一轮实验，应该改变什么

  1. 01

    把真实 acceptance 前移

    每个 checkpoint 都跑一组小型、固定 seed 的 serving eval，不再用 validation proxy 代替选择信号。

  2. 02

    先统一官方评测口径

    用相同 evaluator、164 条 HumanEval、batch 1 与 non-thinking 配置重测三组 checkpoint，再讨论模型差异。

  3. 03

    检查目标函数和数据分布

    优先审计 confidence / Markov loss、训练数据生成方式，以及长位置接受率快速衰减的原因。

  4. 04

    优化在线数据供给

    针对 hidden-state fetch 的 42%–54% 占比做批量、流水化和缓存实验，但保留即用即删的磁盘策略。
