DSpark 在线训练实验：从 Smoke 到 30K

Qwen3-8B online hidden-state 训练、延迟分析与真实 acceptance 评测

硬件

Verifier
Qwen3-8B
状态
已完成

摘要

本实验验证 DSpark 在当前 Speculators 和 vLLM 环境中的在线训练流程，并依次完成 smoke、5K pilot 和 30K × 2 epochs 三个阶段。这里的“在线”是指 draft model 训练时按需从冻结的 Qwen3-8B verifier 获取 hidden states，并不更新 verifier 权重。

工程链路可以稳定运行，但训练指标与真实 serving 结果出现明显错配：从 5K 扩展到 30K 后，validation proxy accept length 从 1.9392 提高到 2.850，真实 HumanEval acceptance length 却从 1.514327 降至 1.381908。因此，当前 validation proxy 不适合用于 checkpoint 选择。在继续扩大数据和训练轮数前，应先统一评测口径并检查训练目标与 serving 分布的差异。

1. 实验设置

训练使用一张 GPU 运行 vLLM hidden-state server，其余 GPU 运行 DSpark trainer。Verifier 始终冻结，仅作为多层目标表征的提供者。

Target / verifierQwen3-8B，BF16
Hidden-state serverGPU 0，vLLM 0.26.0
TrainerSmoke 使用 GPU 1；正式训练使用 GPU 1–3 三卡 DDP
Target layers正式训练使用 1、9、17、25、33
Draft model5-layer DSpark；正式 serving 提议 7 draft tokens
AttentionSDPA；当前 PyTorch 2.11 / A100 环境不使用 FlexAttention
Online data policyhidden-state 文件生成后消费并删除（on-generate=delete）

2.1 Smoke

Smoke 使用 4 条本地 ShareGPT 格式对话，其中 3 条训练、1 条验证。GPU 0 运行 verifier，GPU 1 执行单进程训练。最终运行完成 hidden-state 请求、前向与反向传播、一次 optimizer step、验证和 checkpoint 保存。

  • 训练 loss：2.316。
  • 验证 loss：1.365209。
  • 成功运行目录：runs/20260816_175207/。

2.2 5K pilot

Pilot 使用 5,000 条重新生成的 Qwen3-8B 样本，训练一轮，共 1,204 optimizer steps。序列长度为 4096；由于 completion 还会请求一个额外 token，vLLM 的服务上限必须至少设为 4097。

  • 稳态训练速度约 4.1–4.5 秒/step。
  • 在线 hidden-state fetch 约占单步时间的 42%–54%。
  • Validation loss 为 0.7738，proxy accept length 为 1.9392。
  • 真实 HumanEval acceptance length 为 1.514327。

2.3 30K × 2 epochs

30K 实验从 5K 模型权重初始化，但重新初始化 optimizer 和 scheduler。30,000 条样本与 pilot 不重叠，其中 28,500 条用于训练、1,500 条用于验证。两轮共执行 14,425 optimizer steps。

  • 训练主体耗时 13 小时 50 分 40 秒。
  • 包含预处理和两轮评测的端到端耗时为 14 小时 20 分 16 秒。
  • 全程没有 OOM、NaN、NCCL 或 HTTP 错误。
  • Validation 指标继续改善，但两个 epoch 的真实 acceptance 都低于 5K pilot。

3. 在线训练与评测流程

3.1 训练流程

  1. 准备对话数据，完成 tokenize 和 train / validation split。
  2. 在 GPU 0 启动冻结的 Qwen3-8B vLLM hidden-state server。
  3. GPU 1–3 上的 trainer 为当前样本请求缺失的目标层 hidden states。
  4. vLLM 返回指定层表征；trainer 消费对应文件后立即删除。
  5. DSpark 计算 token CE、TV distribution matching、confidence 和 Markov 相关损失。
  6. 各 DDP rank 完成 optimizer step，按周期执行 validation 并保存 checkpoint。

3.2 真实 acceptance 评测

  1. 将训练 checkpoint 转换到隔离的 serving 目录。
  2. 使用 vLLM V2 runner 加载 Qwen3-8B target 和 DSpark draft model。
  3. 使用 Speculators evaluator 和 GuideLLM 发送 HumanEval 请求。
  4. 从 serving metrics 汇总 draft 数、accepted tokens 和逐位置接受率。

训练 validation 的 proxy accept length 不经过完整 serving 路径，因此只能视为代理指标，不能代替真实 speculative decoding acceptance。

5.1 HumanEval 评测口径

三组 checkpoint 使用相同本地口径：Speculators evaluator、vLLM V2、GuideLLM 0.7.3、HumanEval 前 80 条、temperature 1.0、最大并发 8、最大输出 4096。

官方 Qwen3-8B DSpark 报告的 acceptance length 为 5.454539，但使用 DeepSpec evaluator、164 条 HumanEval、batch 1 和 non-thinking。两者不是严格同口径，不能直接排名；当前约四倍差距仍表明本地复现尚未对齐。

7. 结论与后续

  1. 在线 hidden-state 生成、训练、验证、checkpoint 转换和 serving 评测链路均已跑通。
  2. 扩大到 30K 数据和两轮训练显著改善离线 validation，但没有提高真实 acceptance。
  3. 当前 validation proxy 不应作为 checkpoint 选择标准。
  4. 下一步应先用官方口径重测三个 checkpoint，再检查 confidence / Markov loss、训练数据生成方式和 evaluator 配置。
  5. 在真实 acceptance 信号稳定前，不建议继续单纯增加数据规模或训练轮数。
