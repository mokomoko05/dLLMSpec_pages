摘要

本实验把每次 speculative verification round 拆成 draft 输入准备、DFlash forward、logits 后处理、union-tree 构造、target verification 和 commit。标准 single@16 每轮 44.156 ms；原始 packed [4,8,16] 为 47.175 ms，慢 6.6%。将三条 packed 路径的 vocabulary projection、refinement head 和 argmax 合并为拼接后的单次操作后，round 降至 45.593 ms，剩余差距为 3.3%。

packed 与 single 的 target 输入形状不同：packed 平均 union tree 为 17.50 个节点、3 条候选路径，因此 target 时间只能解释为本次实现的同口径阶段测量，不等价于完全相同 FLOPs 的微基准。

2. 数据流与计时边界

Tround = Tprepare + Tdraft + Tpostprocess + Tunion + Ttarget + Tcommit + TunattributedTunattributed = Tround,wall − Σmarked phases Tphase

prepare 和 union/commit 使用 GPU 同步后的 wall-clock，因此包含 Python 控制和 tensor 分配；draft_total、target_verify 使用 CUDA event，分别表示 DFlash forward 与 target forward 的 GPU 区间。round wall 是完整同步后的端到端单轮时间。

4. 后处理融合优化

原始实现对三个 segment 分别调用三次 lm_head，再分别调用三次 refinement head 和 argmax。优化代码先把三个 segment 的有效 hidden 拼成一个序列：

Hprop = concat(H0,1:L₀−1, H1,1:L₁−1, H2,1:L₂−1) ∈ R1×(Σ(Lᵢ−1))×DZ = LMHead(Hprop) ∈ R1×(Σ(Lᵢ−1))×VZ′ = Z + Refiner(concat(H0,0:L₀−2, H1,0:L₁−2, H2,0:L₂−2))

其中 D 是 hidden size，V 是 draft vocabulary，Lᵢ 是第 i 个 block 长度。随后按长度 Lᵢ−1 split 回三条 proposal chain，所以 token 顺序和 target verification 输入不变。小张量测试确认优化前后 logits 误差仅为 GEMM reduction 的浮点舍入（最大约 2.4×10−7，argmax 完全一致）。

5. 后续优化

  1. 在 commit 内继续拆分 posterior 读取、Python longest-path walk、output 写回和 _gather_cache，定位 1.327 ms 的具体来源。
  2. 避免 posterior 和 candidate path 的 GPU→CPU 同步；考虑保持紧凑 tensor 表示，仅在最终路径索引处同步。
  3. 缓存固定 block size 下的 position-id/mask 模板，减少每轮 0.56 ms prepare 和 0.65 ms union tensor 分配。
  4. 最后再评估 tree-aware target attention kernel；当前 target 已不比 single 慢，优先级低于控制路径。

后续每项改动都必须在相同模型、数据、GPU、SDPA、样本数和 warm-up 口径下重新 profile；未复测前不宣称端到端收益。
